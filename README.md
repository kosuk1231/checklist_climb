# 등반대회 준비물 3단 체크리스트

2026 서울사회복지사 등반대회(2026. 9. 12.) 준비물 72항목을
**9. 10. 패킹 → 9. 11. 최종 확인 → 9. 12. 현장 반입** 3단계로 나눠 체크하는 웹앱입니다.

- 프런트: 정적 HTML 1개 (빌드 없음) → Vercel
- 백엔드: Google Apps Script 웹앱 → Google 스프레드시트
- 통신: JSONP (CORS 설정 불필요)

```
checklist/
├─ public/
│  ├─ index.html      현장용 체크 화면
│  ├─ theme.css       세 페이지 공통 디자인 토큰
│  ├─ fonts/          Pretendard Variable 자체 호스팅 (다이내믹 서브셋 92개)
│  ├─ guide.html      직원용 당일 안내 (타임라인·사람별·개회식·장소·연락망)
│  ├─ admin.html      관리자 화면 (PIN 잠금)
│  ├─ config.js       ★ GAS 웹앱 URL 입력
│  └─ items.js        준비물 마스터 72항목 (오프라인 폴백)
├─ apps-script/
│  ├─ Code.gs         준비물 시트 API + 시드
│  └─ Guide.gs        당일 안내 시트 API + 시드
├─ vercel.json
└─ README.md
```

## 1단계 — Apps Script 배포

1. <https://script.google.com> 에서 새 프로젝트를 만들고 `apps-script/Code.gs` 내용을 붙여넣습니다.
   그리고 파일 상단의 `ADMIN_KEY` 를 원하는 PIN으로 바꿉니다 (기본값 `sasw2026`).
   좌측 파일 목록에서 `+` → 스크립트로 파일을 하나 더 만들고 이름을 `Guide` 로 지정한 뒤
   `apps-script/Guide.gs` 내용을 붙여넣습니다.
2. 상단에서 함수 `seed` 를 실행하고, 이어서 `guideSeed` 도 실행합니다.
   - 스프레드시트에 `준비물체크리스트` 시트가 생기고 72항목이 입력됩니다.
   - 최초 실행 시 스프레드시트 접근 권한 승인이 필요합니다.
3. **배포 → 새 배포 → 유형: 웹 앱**
   - 설명: `등반대회 체크리스트 API`
   - 실행: **나(본인 계정)**
   - 액세스 권한: **모든 사용자**
4. 발급된 URL(`.../exec`)을 복사합니다.

> 시트 ID는 `Code.gs` 상단 `SHEET_ID` 에 이미 넣어 두었습니다.
> `1PQy4OPfn3ldPuudmJwKzJtiOm8itfUPEpORyYqWfXlo`

## 3단계 — GitHub → Vercel

```bash
cd checklist
git init
git add .
git commit -m "등반대회 준비물 3단 체크리스트"
git branch -M main
git remote add origin https://github.com/<계정>/climb-checklist.git
git push -u origin main
```

Vercel에서 New Project → 이 저장소 선택 → 프레임워크는 **Other**,
`vercel.json`이 `outputDirectory: public`을 잡아 주므로 나머지는 기본값으로 배포합니다.

CLI로 바로 올리려면:

```bash
npx vercel --prod
```

## 화면 사용법

| 기능 | 설명 |
|---|---|
| 상단 3개 탭 | 확인 단계 전환. 단계마다 색이 달라 지금 무엇을 체크하는지 헷갈리지 않습니다 (패킹=파랑 / 확인=주황 / 당일=빨강) |
| 구분별 / 사람별 | 13개 구분으로 보거나, 18명 담당자별로 봅니다. 사람별에서는 남은 항목이 많은 사람이 위로 올라옵니다 |
| 담당자 선택 | 특정 담당자 것만 필터. 진행률도 그 사람 기준으로 다시 계산됩니다 |
| 남은 것만 | 현재 단계에서 아직 체크 안 된 항목만 표시 |
| 확인한 사람 | 이름을 입력하면 체크할 때 시트 `0910확인자` 등 칸에 함께 기록됩니다 |
| 행 오른쪽 작은 점 | 다른 두 단계의 체크 상태. 9/11 화면에서도 9/10에 챙겼는지 바로 보입니다 |

주소창 해시에 상태가 남아서(`#me=고석우&s=1&v=person`) 그대로 공유하면
상대방이 같은 화면으로 열립니다. 담당자별 링크를 카톡으로 뿌릴 때 편합니다.

## 시트 구조

`준비물체크리스트` 시트

| 열 | 내용 |
|---|---|
| A | id (RCP01 …) — 절대 바꾸지 마세요. 체크 저장 키입니다 |
| B~E | 구분 / 준비물 / 수량 / 담당 |
| F~H | 0910 / 0911 / 0912 체크박스 |
| I~K | 각 단계 확인자 |
| L | 갱신시각 |
| M | 메모 |

`체크로그` 시트에 체크·해제 이력이 시각·항목·확인자와 함께 누적됩니다.
당일 누가 언제 확인했는지 확인할 때 씁니다.

### 항목을 고칠 때

시트에서 B~E 열을 직접 고쳐도 됩니다.
항목을 추가·삭제할 때는 `apps-script/Code.gs`의 `ITEMS` 와
`public/items.js` 의 `CHECKLIST_ITEMS` 를 **양쪽 모두** 수정한 뒤
스프레드시트 메뉴 `등반대회 체크리스트 → 항목 다시 쓰기(체크 유지)` 를 실행하세요.
기존 체크 상태는 id 기준으로 유지됩니다.

## 직원용 당일 안내 (`/guide.html`)

9/12(토) 당일 순서·업무분장을 보는 정적 페이지입니다. 백엔드 없이 데이터가 파일 안에 있어
수정하려면 `guide.html` 상단 스크립트의 `TL`(타임라인) · `MATRIX`(개인별) 을 고치고 재배포합니다.

- 상단 **내 이름** 을 고르면 타임라인에서 내 업무가 파란 띠로 강조되고, 사람별 탭이 내 이름으로 열립니다.
  `guide.html#me=최봄` 처럼 링크로 보내면 열자마자 그 사람 기준으로 보입니다.
- 행사 당일에는 현재 시각 기준 진행 중인 시간대에 **지금** 표시가 붙고 상단에 빨간 띠로 안내됩니다.
- 하단 탭: 시간(타임라인) / 사람(내 업무) / 식순(개회식 큐시트) / 장소(코스·부스·동선·주차·식사) / 연락(비상연락·판단순서·숫자)

### 당일 안내 편집

`guide.html` 오른쪽 위 **편집** 버튼 → 관리자 PIN 입력 → 편집 모드로 들어갑니다.
PIN은 `Code.gs` 의 `ADMIN_KEY` 와 같습니다.

| 대상 | 방법 |
|---|---|
| 업무 내용 | 항목의 `수정` → 장소·업무·총괄·지원·유의사항 |
| 업무 순서 | `↑` `↓` (같은 시간대 안에서만 이동) |
| 업무 추가 | 시간대 맨 아래 `+ 이 시간대에 업무 추가` |
| 업무 삭제 | `수정` 안의 `삭제` |
| 시간대 자체 | 왼쪽 시각(점선 밑줄)을 눌러 시작·종료·구간 이름 변경 |
| 개인별 업무 | 내 업무 탭에서 시간 칸을 눌러 수정. 여러 건은 ` / ` 로 구분 |
| 개회식 큐시트 | 개회식 탭에서 줄을 눌러 시간·순서·담당 수정 |
| 주관 단체 | 개회식 탭에서 이름을 눌러 수정 · 추가 · 삭제 |
| 주요 내빈 | 개회식 탭에서 이름을 눌러 수정. 구분 변경, `↑` `↓` 순서 이동, 추가·삭제 가능. 구분 드롭다운에서 `+ 새 구분 직접 입력` 선택 시 새 그룹 생성 |

저장은 즉시 시트에 반영되고 `체크로그` 시트에 `관리` 로 기록됩니다.
편집 모드에서는 하단 탭으로 다른 화면에 가도 모드가 유지되며,
`편집 끝내기` 를 누르거나 탭을 닫으면 해제됩니다(PIN은 저장하지 않음).

**최초 1회**: Apps Script 편집기에서 `guideSeed` 를 실행해야 시트 6개(당일시간블록·당일업무·당일시간구간·개인별업무·개회식큐시트·주관단체·주요내빈)가 만들어집니다.
실행 전에는 `guide.html` 이 파일에 내장된 기본값을 보여주며, 편집을 시도하면 안내가 뜹니다.
`guideSeedReset` 은 안내 시트를 코드의 기본값으로 되돌립니다.

**오프라인 대비**: 시트를 읽지 못하면 `guide.html` 에 내장된 기본값이 그대로 표시됩니다.
현장에서 통신이 끊겨도 화면은 뜹니다(편집만 안 됨).

## 관리자 화면 (`/admin.html`)

`Code.gs` 의 `ADMIN_KEY` 를 입력하면 열립니다. PIN은 어디에도 저장되지 않아서
탭을 닫으면 다시 물어봅니다. 현장용 체크 화면 하단의 `관리` 링크로 갈 수 있습니다.

| 기능 | 설명 |
|---|---|
| 항목 추가 | 구분을 고르면 id가 자동 생성되고(`RCP10` 등) 같은 구분 맨 아래에 끼워 넣습니다. `+ 새 구분 직접 입력`으로 없는 구분도 만들 수 있습니다(id는 `NEW01`부터) |
| 항목 수정 | 목록에서 `수정` → 구분·준비물·수량·담당·메모를 고쳐 저장. 체크 상태는 그대로 유지됩니다 |
| 항목 삭제 | 수정 패널 안의 `삭제`. 확인창을 거치고, 되돌릴 수 없습니다 |
| 순서 변경 | `↑` `↓` 로 시트 행 순서를 바꿉니다. 체크 화면의 표시 순서가 이 순서를 따릅니다 |
| 담당자 일괄 변경 | 사람이 교체됐을 때. 이름 단위로 정확히 매칭해 바꾸므로 `이진선, 정소희` 같은 복수 담당도 안전합니다. 바꿀 이름을 비우면 그 사람만 담당에서 빠집니다 |
| 구분 일괄 변경 | 구분 이름을 통째로 바꿉니다 |
| 단계 체크 초기화 | 9/10·9/11·9/12 중 한 단계의 체크와 확인자만 비웁니다. 항목은 남습니다 |
| items.js 내보내기 | 현재 시트 내용을 `items.js` 코드로 만들어 줍니다 |

### 항목을 고친 뒤

시트가 항상 정답이라서 체크 화면은 바로 최신 목록을 읽습니다.
다만 `items.js` 는 네트워크가 끊겼을 때 쓰는 폴백이라 그대로 두면 옛 목록이 남습니다.
항목을 여러 개 손봤다면 관리자 화면 맨 아래에서 코드를 만들어
`public/items.js` 의 `window.CHECKLIST_ITEMS = [...]` 부분을 바꿔치기하고 다시 배포해 주세요.
급하지 않으면 안 해도 동작에는 문제가 없습니다.

### 변경 이력

항목 추가·수정·삭제와 일괄 변경은 모두 `체크로그` 시트에 `관리` 표시로 함께 남습니다.
누가 무엇을 언제 바꿨는지 여기서 확인합니다.

## API

| 호출 | 결과 |
|---|---|
| `?action=list` | 전체 항목 + 체크 상태 (공개) |
| `?action=set&id=RCP01&stage=0910&value=1&actor=고석우` | 체크 저장 (공개) |
| `?action=note&id=RCP01&text=...` | 메모 저장 (공개) |
| `?action=stats` | 단계별 완료 수 (공개) |

아래는 모두 `&key=<ADMIN_KEY>` 가 필요합니다.

| 호출 | 결과 |
|---|---|
| `?action=auth` | PIN 확인 |
| `?action=add&cat=..&name=..&qty=..&who=..` | 항목 추가 |
| `?action=update&id=..&name=..&who=..` | 넘긴 항목만 수정 |
| `?action=remove&id=..` | 항목 삭제 |
| `?action=move&id=..&dir=up` | 순서 이동 |
| `?action=renameWho&from=..&to=..` | 담당자 일괄 변경 (to 생략 시 제거) |
| `?action=renameCat&from=..&to=..` | 구분 일괄 변경 |
| `?action=resetStage&stage=0910` | 단계 체크 초기화 |
| `?action=export` | items.js 코드 |
| `?action=seed` / `&force=1` | 항목 다시 쓰기 / 전체 초기화 |

모든 호출에 `&callback=fn` 을 붙이면 JSONP로 응답합니다.

## 보안 수준에 대해

PIN은 GAS 안의 상수 하나로 검사합니다. 조직 내부용으로는 충분하지만,
관리자 화면 주소를 아는 사람이 PIN을 알아내면 항목을 고칠 수 있습니다.
관리 URL과 PIN은 사무처 안에서만 공유하고, 행사가 끝나면
`ADMIN_KEY` 를 바꿔서 재배포하시는 편이 좋습니다.
